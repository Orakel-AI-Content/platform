# 0001 – Entrada do scaffold da raiz

- Status: aceito
- Data: 2026-09-29

## Contexto

A raiz do monorepo foi gerada pela skill `/scaffold` (modo `root`) a partir de um
payload de decisões de arquitetura. Este ADR guarda o texto integral da entrada, que é
a origem (`input_ref`) dos itens `source: input` de `docs/project-spec.yaml`.

## Decisão

Texto da entrada, sem edição:

> # Scaffold — Monorepo `platform` (base comum)
>
> Plataforma Orakel AI: rede de 5 a 20 sites de conteúdo gerados a partir de uma única base de código (single codebase, multi-instance), com Backoffice próprio, geração de conteúdo com LLM e revisão humana. Time de 1 pessoa. Este bloco define a base comum do repositório `Orakel-AI-Content/platform`, criada na fase 0 do MVP (ambiente local ponta a ponta, em containers, antes do primeiro deploy).
>
> | Tópico                    | Definido                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
> | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
> | Organização               | Monorepo único com pnpm workspaces + Turborepo (grafo de dependências, cache de tarefas, CI só no que o commit afetou). Não existe repositório por site                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
> | Linguagem e runtime       | TypeScript em modo estrito; versões fixadas de Node, pnpm, Postgres e das imagens de apoio                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
> | Design de código          | Lógica de domínio em pacotes TypeScript agnósticos de framework; camada fina de adaptador por framework. Código único, sem fork por site: tudo que varia entre sites é configuração                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
> | `packages/content-model`  | Schemas Zod do conteúdo e da configuração de site, compartilhados entre o Backoffice (quem envia) e o build (quem consome). `schemaVersion = 1` e a lista de recursos suportados pela versão (tipos de bloco, presets, variantes, perfil de imagem). Configuração do site: domínios, idioma, fuso, flag `indexavel`, tema, presets por tipo de página, variantes, feature flags, sobrescrita da lista de crawlers, textos institucionais, integrações. Catálogo inicial de blocos: texto (rich text restrito), sumário, citação, imagem (texto alternativo obrigatório ou marcada como decorativa), FAQ; todo bloco tem `type` e `n` (número estável no artigo, nunca reutilizado). Validação semântica além do schema. Evolução só aditiva dentro de uma versão; mudança incompatível cria a versão seguinte; o parse ignora campos desconhecidos |
> | `packages/content-client` | Cliente da API de exportação do Backoffice: loader do Content Layer do Astro para o build (lê NDJSON em streaming e valida cada linha) e leitura ao vivo para a visualização                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
> | `packages/core`           | SEO (title, description, canonical, Open Graph, JSON-LD Article, BreadcrumbList, Person, Organization), sitemap, RSS, `robots.txt`, `_redirects`, `_headers`; funções puras com testes unitários                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
> | `packages/tokens`         | Um JSON por tema → variáveis CSS (cores, tipografia, espaçamento, raios, sombras). Os pares de cor passam pela fórmula de contraste da WCAG; abaixo de AA, o build do pacote falha                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

> | `packages/events`         | Formato versionado dos eventos: payload, layout posicional do Analytics Engine e mensagem de fila; usado pelo Worker de borda e pelo agregador                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
> | `packages/ui`             | Ilhas React, só quando uma interação não se resolve com CSS nem Web Component. Sem CSS-in-JS com runtime (CSS Modules com as variáveis dos tokens); sem APIs exclusivas de framework                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
> | `adapters/astro`          | Integração Astro                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
> | Lint e format             | ESLint e Prettier com configuração compartilhada em `tooling/`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
> | Testes                    | Vitest nos pacotes e módulos de domínio; Playwright para E2E e axe                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
> | Dependências              | Renovate; correções de segurança em até 7 dias, críticas do Next.js ou do React em até 48 h                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
> | Configuração e segredos   | `.env.example` na raiz com todas as variáveis que mudam entre local e produção; `.env.local` fora do Git. Nenhum segredo de produção no GitHub. Variáveis (nomes _proposta_): `ACCESS_TEAM_DOMAIN`, `ACCESS_JWKS_URL`, `ACCESS_AUD`, `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `DEPLOY_TARGET`, `AE_SQL_TRANSPORT`, `AE_SQL_URL`, `IMAGE_REGISTRY`, `BR_BACKUP_ENDPOINT`, `HEARTBEAT_BASE_URL`, `SENTRY_DSN`, `LIGHTHOUSE_PROVIDER`. Fora delas, local e produção se comportam igual                                                                                                                                                                                                                                                                                                                                              |
> | CI                        | GitHub Actions (plano Free), sem segredos. `ci.yml` em todo PR e na `main`: lint, typecheck, Vitest, teste de contrato da API de exportação, build de dois sites de exemplo com orçamento de JS, axe e paridade estático × SSR. `images.yml` (imagens do Backoffice e serviços no GHCR a cada merge na `main`, tag por commit) e `release.yml` (imagem `site-builder` na tag `core-vX.Y.Z`) escritos nesta fase, usados a partir do primeiro deploy. Filtros de caminho: sites e pacotes, Backoffice e serviços, infraestrutura, só documentação. E2E completo só local ou em workflow manual                                                                                                                                                                                                                                                      |
> | Git                       | Branch `main`, sem proteção de branch enquanto o time tiver uma pessoa. Releases do core por tag manual `core-vX.Y.Z` (semver: major muda o schema da API ou exige migração de configuração; minor, funcionalidades; patch, correções). Merge na `main` não cria release                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
> | Comandos                  | Na raiz (_proposta_): `pnpm local:up` (sobe e migra), `local:seed`, `local:down`, `local:reset` (apaga volumes), `local:images` (constrói as imagens com as tags de produção), `local:e2e`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
